# 2k9s

Pick an AWS account from a list, then open `k9s` straight into that account's EKS cluster.

Replaces the manual steps you'd otherwise repeat every time you switch clusters:

```bash
aws sso login --profile <account>
aws eks update-kubeconfig --region <region> --name <cluster> --alias <cluster>
k9s --context <cluster>
```

The tool isn't tied to any organization. Everything org-specific lives in your own config, generated by `2k9s init`. The binary works on any machine, with any AWS Identity Center.

---

## Build and install

Requires Go (`brew install go`). `aws`, `kubectl`, `k9s`, `fzf` don't need to be installed beforehand — the first time you run `2k9s` it will offer to install them.

```bash
cd ~/Documents/2k9s
make install
```

`make install` builds the `2k9s` binary and copies it into `~/.local/bin/`.

> **Binary name.** Don't run `go build .` — Go names the output after the module path (`twok9s`), so you'd end up with a file named `twok9s`. Always use `make build` or `go build -o 2k9s .`.

### Check it's usable from anywhere

```bash
cd ~
2k9s --check
```

If you see `command not found: 2k9s`, see the section below.

## Export PATH

`~/.local/bin` is usually already in `PATH`. Only do this step if `2k9s --check` reports `command not found`.

For **zsh**:

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

For **bash**: replace `~/.zshrc` with `~/.bashrc`.

Check:

```bash
echo $PATH | tr ':' '\n' | grep local/bin
which 2k9s
```

### Alternative: run in place, no binary copy

```bash
echo 'export PATH="$HOME/Documents/2k9s:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

Handy while still editing code: after `make build` you're immediately using the new build, no need to `make install` again.

### Install somewhere else

```bash
make install PREFIX=/usr/local/bin
```

## First run

```bash
2k9s init
```

`init` does 4 things:

1. **Auto-discovers SSO instances** already on the machine — scans `~/.aws/sso/cache` and `~/.aws/config`, gathers `sso_start_url` values with their `sso_region`, and lets you pick. On a clean machine that's never logged in, it asks you to type in the URL + region.
2. **Asks for an org name** — used with `--org`. Defaults to something derived from the start URL's hostname.
3. **Asks for region(s) to search for EKS clusters** — comma-separated for multiple regions.
4. **Imports accounts** — calls `aws sso list-accounts`, fetching exactly the accounts you've been granted access to. If there's no token yet, it runs `aws sso login` first.

No need to type the account list by hand. The source of truth is AWS SSO.

For multiple organizations, run `2k9s init` multiple times, once per org. The config can hold several orgs at once.

### Updating accounts later

```bash
2k9s sync                 # sync all orgs
2k9s sync --org <name>    # just one org
```

`sync` merges by **account ID**:

- a new account in SSO → added, printed as `+ <name> (<id>)`
- an existing account → keeps the name you've edited by hand, only fills in the email if it was previously empty
- an account no longer visible in SSO → printed as `- <name>` as a warning but **stays** in config, never auto-deleted

## Account list source: config schema

Config lives at `~/.config/2k9s/config.json`. Lookup order:

1. the `TWOK9S_CONFIG` environment variable
2. `$XDG_CONFIG_HOME/2k9s/config.json`
3. `~/.config/2k9s/config.json`

```bash
2k9s config path      # print the path
2k9s config show      # print the contents
2k9s config edit      # open with $EDITOR
```

### Schema

```json
{
  "version": 1,
  "orgs": [
    {
      "name": "example-org",
      "sso_start_url": "https://example-org.awsapps.com/start",
      "sso_region": "ap-southeast-1",
      "default_regions": ["ap-southeast-1", "us-east-1"],
      "login_profile": "2k9s-login-example-org",
      "role_preference": ["PlatformAdmin", "AWSAdministratorAccess"],
      "imported_at": "2026-09-04T07:00:00Z",
      "accounts": [
        {
          "name": "xxxxx",
          "id": "xxxxx",
          "email": "xxxxx@example-org.com"
        }
      ]
    }
  ]
}
```

### Constraints

Config is validated on every read and every write. If it doesn't match the schema, the tool reports a specific error instead of running incorrectly.

| Field | Required | Rule |
|---|---|---|
| `version` | yes | must be `1` |
| `orgs` | yes | at least 1 element |
| `orgs[].name` | yes | `^[A-Za-z0-9][A-Za-z0-9._-]{0,31}$`, must not collide with another (case-insensitive) |
| `orgs[].sso_start_url` | yes | must start with `https://` |
| `orgs[].sso_region` | yes | an AWS region code, e.g. `ap-southeast-1` |
| `orgs[].default_regions` | yes | at least 1 valid region code |
| `orgs[].login_profile` | no | the profile name used for `aws sso login`. Left blank, the tool auto-creates `2k9s-login-<org>` |
| `orgs[].role_preference` | no | role priority order. Left blank, falls back to AWS Identity Center's default list |
| `orgs[].accounts[].name` | yes | `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`, **no whitespace**, must not collide within the same org |
| `orgs[].accounts[].id` | yes | a **string** of exactly 12 digits, must not collide within the same org |
| `orgs[].accounts[].email` | no | reference only, not used for authentication |

Three easy mistakes:

**`id` must be a string, not a number.** Some account IDs start with `0` (e.g. `012345678912`). As a JSON number, the leading zero would be lost and the account would be wrong.

**`name` must not contain whitespace**, since it's used directly as the AWS profile name in `~/.aws/config` and as the `AWS_PROFILE` value in kubeconfig. When importing from SSO, account names are auto-normalized: lowercased, unusual characters turned into `-`, and a `-2` suffix added on collision. Example: `Workload Prod (AWS)` → `workload-prod-aws`.

**`name` is the field you're allowed to edit.** `sync` matches by `id`, so renaming is safe — the next sync won't overwrite it.

### Importing from a flat file

If you already have a list in plain text:

```bash
2k9s import -file accounts.txt
2k9s import -file accounts.txt -org example-org    # override the org name
```

File format:

```
# org: example-org
# sso-start-url: https://example-org.awsapps.com/start
# sso-region: ap-southeast-1
# default-regions: ap-southeast-1,us-east-1
# login-profile: my-profile
# role-preference: PlatformAdmin,AWSAdministratorAccess

xxxxx,xxxxx,xxxxx@example-org.com
example-uat,012345678912,example-uat@example-org.com
```

Rules: `# key: value` lines at the top are directives; data lines are `name,id[,email]`; blank lines and regular comments are skipped. Without `# org:`, the org name is taken from the filename. An `id` that isn't exactly 12 digits raises an error with the line number.

`import` also merges by `id`, same as `sync`.

## Daily use

```bash
2k9s                      # pick account -> pick cluster -> open k9s
2k9s -c                   # quick-pick from an existing kubeconfig context, no AWS calls
2k9s --org example-org    # only show accounts from one org
2k9s -n kube-system       # open k9s in the given namespace
2k9s -l                   # print the account list
2k9s --dry-run            # show what would happen, write nothing, don't open k9s
2k9s --check              # check aws/kubectl/k9s/fzf
```

### Help

```bash
2k9s --help          # full guide: commands, examples, flags
2k9s -h              # same as above
2k9s help            # same as above
2k9s init --help     # per-command help
2k9s sync --help
2k9s import --help
2k9s config --help
```

With `fzf` installed, type to filter the list. Without it, falls back to a numbered list.

`2k9s -c` is the fastest option for everyday use: reads the existing kubeconfig, no AWS API calls.

### Flags

| Flag | Meaning |
|---|---|
| `-a <account>` | pick an account directly by name, skipping the list |
| `-cluster <name>` | pick a cluster directly by name |
| `--region <list>` | override `default_regions` |
| `--add-region <r>` | also search this region in addition to `default_regions` |
| `--refresh` | skip the cache, call `eks list-clusters` again |
| `--no-k9s` | only set kubeconfig, don't open k9s |
| `--no-login` | don't auto-run `aws sso login` |
| `--write-profile=false` | don't auto-add a profile to `~/.aws/config` |
| `-y` | if tools are missing, install them without asking |
| `--no-install` | don't auto-install tools |

A handy alias:

```bash
echo "alias kk='2k9s -c'" >> ~/.zshrc
```

## Where the tool writes

| File | When | What |
|---|---|---|
| `~/.config/2k9s/config.json` | `init`, `sync`, `import` | the org + account list. Backed up as `config.json.bak-<timestamp>` before writing, written via a temp file then renamed so a half-written config is never left behind |
| `~/.aws/config` | picking an account without a profile yet | appends `[profile <account>]`. Backed up as `config.bak-2k9s-<timestamp>` first. Never modifies an existing profile. Disable with `--write-profile=false` |
| `~/.aws/config` | logging in when the org has no `login_profile` yet | appends `[profile 2k9s-login-<org>]` with just `sso_start_url` + `sso_region`, enough for `aws sso login` |
| `~/.kube/config` | after picking a cluster | via `aws eks update-kubeconfig --alias <cluster>` |
| `~/.cache/2k9s/clusters.json` | after listing clusters | 24h cache. Clear it with: `rm -rf ~/.cache/2k9s` |

Why the profile has to be written to `~/.aws/config`: `aws eks update-kubeconfig` generates an exec block with `AWS_PROFILE`, so the context needs a matching profile to keep working on later runs.

`2k9s --dry-run` prints exactly what it would do without writing anything.

## Troubleshooting

**`command not found: 2k9s`** — see [Export PATH](#export-path).

**Binary built as `twok9s`** — missing `-o`. Use `make build`.

**`no config yet ... run 2k9s init`** — accounts haven't been imported yet. `2k9s` with no subcommand automatically runs `init` if config is missing.

**`org "x" already exists in config`** — use `2k9s sync --org x` to refresh accounts, or `2k9s init --force` to overwrite the org's config.

**`sso list-accounts returned no accounts`** — the token is valid but the user hasn't been granted any account in that Identity Center.

**`you have no SSO role in account`** — the user has no permission set on that account. Not a tool bug.

**`no EKS clusters found`** — the cluster is in a region other than `default_regions`. Try `2k9s --add-region <region>`, or edit `default_regions` with `2k9s config edit`.

**Wrong role picked** — add `role_preference` for the org with `2k9s config edit`.

## Version & release

Check the running version:

```bash
2k9s version
# or
2k9s --version
```

A manual build (`make build`) automatically tags the version from `git describe` (e.g. `v1.2.3` or
`v1.2.3-2-gabc1234` if there are commits after the tag); without a tag/git it shows `dev`.

To publish a new release on GitHub (prebuilt for Linux amd64/arm64 and
macOS arm64, attached to the GitHub Release), just tag and push:

```bash
git tag v1.2.3
git push origin v1.2.3
```

GitHub Actions (`.github/workflows/release.yml`) will build automatically, embed the right
version into the binary via `-ldflags -X main.version=...`, then create a release with the
`.tar.gz` + `.sha256` files for each platform. The tag must follow `v<major>.<minor>.<patch>`
(e.g. `v1.0.0`) — without the `v` prefix or in the wrong format, the workflow won't run.

## Development

```bash
make fmt      # gofmt
make vet      # go vet
make build    # produces ./2k9s
make clean    # remove the binary
```

No dependencies outside the standard library. All AWS interaction goes through the `aws` CLI instead of the SDK, to share the SSO token cache with `aws` and keep the binary lightweight.

| File | Purpose |
|---|---|
| `main.go` | flags, subcommand dispatch, the 2 main flows (account / context) |
| `config.go` | config schema, validation, atomic load/save |
| `cmd_config.go` | `init`, `sync`, `import`, `accounts`, `config`; auto-discovers SSO instances |
| `deps.go` | step 0: check for and install `aws`/`kubectl`/`k9s`/`fzf` |
| `accounts.go` | runtime types, flat-file import, merge by account ID |
| `aws.go` | SSO token, role discovery, EKS, `~/.aws/config`, kubeconfig |
| `pick.go` | the picker: fzf or a numbered-list fallback |
| `cache.go` | cluster list cache |

Don't commit the binary — `.gitignore`:

```
2k9s
twok9s
```
